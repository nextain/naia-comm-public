# Discord와 GitHub를 함께 쓰는 방법

Discord는 질문·발견·논의의 입구다. 작업 범위·결정·검증·승인은 GitHub 이슈와 PR에 남긴다. Discord에 참여하지 않아도 GitHub만으로 기여할 수 있다. 로컬 개발에는 서버 계정이나 봇 등록이 필요 없다.

## 처음에는 세 공간이면 충분하다

- 시작/공지: 저장소·기여 안내 링크와 검증된 릴리스 공지. 운영진만 공지를 작성한다.
- 질문/기여 forum: 질문·재현·첫 기여·검토 요청을 태그로 분류한다. 하나의 이슈에 스레드 하나를 연결한다.
- 일상 대화: 자유 대화. 여기서 나온 작업 결정은 담당자가 이슈에 요약한다.

이 이름은 제안이며 채널이나 봇이 이미 구성됐다는 뜻이 아니다. 처음부터 제품마다 채널을 만들지 않고 활동량과 moderation 필요가 생기면 분리한다. 시간대가 달라도 참여할 수 있도록 회의는 선택 사항이고 결정은 텍스트로 남긴다.

스레드 제목 예시는 `nextain/naia-shell#123 · 음성 입력 재현`이다. 번호는 형식 예시다. 실제 이슈 URL을 첫 메시지에 붙인다. `naia-shell#123`과 `naia-agent#123`은 다른 작업이므로 숫자만으로 연결하지 않는다. 여러 저장소 논의는 coordination 이슈 한 곳을 연결하고 구현 PR은 그 이슈에서 추적한다.

검토 요청에는 대상 reviewer, 확인할 내용, 정확한 commit/PR, 결과를 남길 위치를 적는다. 채팅에서 해결했어도 담당자가 공개 가능한 결정과 근거를 GitHub에 요약한다. 전체 대화·첨부·개인 DM을 GitHub에 자동 복제하지 않는다. 원시 음성·기억 DB·개인 대화 대신 합성 재현 예제를 사용한다.

## 선택적 자동화

초기에는 사람이 링크와 요약을 남기면 된다. 봇이 필요해지면 알림만 보내는 최소 권한으로 시작한다. 이 repo에는 게이트웨이 구현이 없다. 봇 운영 시 하나의 토큰을 한 소비자만 소유하고, 토큰과 실제 사용자 ID 연결은 공개 저장소 밖에서 관리한다. 중복 소비자는 새 실행을 거부한다.

공개 메시지나 DM으로 코딩·shell 실행·병합·배포를 요청하는 경로는 기본적으로 비활성이다. Discord 역할은 GitHub 권한이 아니다. 개인이 선택한 로컬 AI도 해당 작업자의 승인과 제품 저장소 규칙을 따른다. 공용 서버 실행을 도입하려면 격리·인증·허용 명령·권한·감사를 별도 설계해야 한다. 기존 `schemas/participants.schema.json`은 그런 선택적 서버 adapter의 호환 자료로만 보존하며 기본 가입 절차에 쓰지 않는다.

기존 참여 조사 사이트의 운영자 설정 webhook은 설문 알림 기능이며, 여기서 제안하는 대화 봇이나 코드 실행 게이트웨이와 별개다. 해당 사이트 설정·배포는 기존 프로젝트 안내를 따른다.

괴롭힘·개인정보 노출은 서버 moderator에게 비공개로 알린다. 보안 취약점은 해당 repo의 private vulnerability reporting이 활성화돼 있으면 그 경로를 사용하고, 없다면 maintainer에게 비공개 접수 경로를 요청한다. 공개 채널에 exploit·token을 게시하지 않는다.
