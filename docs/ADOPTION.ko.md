# 표준 구성 선별 적용

`naia-comm`은 여러 사람이 실제로 참여할 수 있는 공개 커뮤니티 프로젝트로서, 필요한 공통 운영 계약만 선별해 사용합니다.

## 채택

- 저장소 진입점과 프로젝트별 컨텍스트 분리
- GitHub 이슈 중심의 범위·완료 조건·검증 증거 관리
- contributor, reviewer, integrator, release owner의 역할과 권한 분리
- 실패 시 닫히는 병합·배포·공개·중복 게이트웨이 정책
- 구조 검증 스크립트와 지속적 통합(CI)
- 프로젝트 어댑터 템플릿과 공개용 신규 clone 절차
- 후보의 전체 트리·도달 가능한 이력·워크플로·라이선스 검토와 커밋 SHA 고정

## 제외

- 개인 기억·비서·페르소나 중심 기능
- 특정 제품의 내부 요구사항·진행 기록·운영 승인
- 특정 PC, 서버, 계정, 개인 ID, IP, 토큰 정보
- 급여·특허·홍보 등 프로젝트 개발과 무관한 자료
- 벤치마크 제품과 메신저 실험 구현
- 다른 저장소의 Git 이력

## 연결 방향

`naia-adk`는 개인 작업환경을, `naia-pj-adk`는 팀 프로젝트의 공동 규칙과 권한을 담당합니다. `naia-comm`은 두 계보를 복사하지 않고 공개 참여 안내에 필요한 공통 계약만 유지합니다. 실제 참여자는 fork에서 HTTPS 또는 SSH로 clone하고, 이슈·브랜치·PR·독립 검토 절차를 사용합니다.
